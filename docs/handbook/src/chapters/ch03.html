Chapter three

3Running it locally

SATistics runs on a laptop as two processes and one hosted database: the Next.js dev server on port 3000, the FastAPI server on port 8000, and a Supabase project you create for yourself. Supabase is the only integration you must set up. Everything else (AI questions, lesson video search) has a keyless fallback, so you can play every game and read every lesson before you sign up for anything else.

This chapter walks from an empty machine to a working sign-up. It covers the tool versions the code actually needs, the SQL that builds the database, every environment variable either app reads, where to get each key, what still works when a key is missing, and the failures people hit most often on the way. Two files are the short form of this chapter: backend/.env.example and frontend/.env.example. Copy them, fill them in, and come back here when something does not start.

3.1What runs where

The browser only ever talks to the FastAPI server. The frontend does not hold any Supabase key and never calls Supabase directly: sign-up, login, scores, profiles and uploaded material all go through frontend/lib/api/client.ts to the backend, which talks to Supabase with the service-role key. That is why the frontend needs exactly one variable and the backend needs the rest.

3.3The database

Create a new project at supabase.com. Any region and the free tier are fine. When it is ready, open the SQL Editor and run the files in backend/database/. There are five, and they are not a numbered migration series. Two of them are the ones you run on a fresh project: 

backend/database/
reset.sql                     drops and recreates game_sessions, question_attempts,
                              user_stats, profiles, the set_updated_at() trigger
                              function, indexes and RLS policies; deletes every auth user
add_materials.sql             materials and custom_questions, their indexes and RLS
add_profiles.sql              profiles only (already included in reset.sql)
add_user_id_to_attempts.sql   adds question_attempts.user_id to an old schema.sql database
schema.sql                    the original three tables, without user_id or profiles

For a new project, run reset.sql and then add_materials.sql, in that order. reset.sql is the complete current schema for the core tables, but it does not create the two tables behind "My material" uploads, and the materials pages fail with a missing table error until add_materials.sql has run. The other three files exist for databases created before reset.sql did; you do not need them on a fresh project. Chapter 13 describes every table and policy.

reset.sql deletes all users The file starts with DROP TABLE IF EXISTS ... CASCADE for every core table and then runs DELETE FROM auth.users;. Every account in the project, and through the ON DELETE CASCADE foreign keys every row that belongs to one, is gone. Run it only on a new project or a development project you are happy to wipe. Never run it against production, and never paste it into a SQL Editor tab without checking which project is selected.

Unlike reset.sql, add_materials.sql is additive and safe to run again: it uses CREATE TABLE IF NOT EXISTS and CREATE INDEX IF NOT EXISTS, and drops each policy before creating it.

One Auth setting matters for local work. Supabase enables "Confirm email" by default. With it on, POST /api/auth/signup creates the user but returns no session, and the backend answers "Please check your email to verify your account". For a development project, turn it off under Authentication, Sign In / Providers, Email, so a sign-up logs you straight in.

3.4Environment variables

The backend loads backend/.env with python-dotenv. Three modules do it independently: src/main.py, src/config.py and src/utils/database.py each look for .env one level above src/. The frontend reads frontend/.env.local, which Next.js loads automatically. Both real files are ignored by the root .gitignore; the .env.example files are explicitly un-ignored so they stay in git. 

cp backend/.env.example backend/.env
cp frontend/.env.example frontend/.env.local

This is every variable the code reads, found by searching for os.getenv and process.env.

Two more names are read but change nothing. src/config.py reads SUPABASE_ANON_KEY into a constant no module imports, and its SUPABASE_SERVICE_KEY constant is likewise unused; only the lookups in src/utils/database.py decide which key the client gets. The lookup order there is: 

# backend/src/utils/database.py, Database.get_client()
supabase_url = os.getenv("SUPABASE_URL") or os.getenv("NEXT_PUBLIC_SUPABASE_URL")
supabase_key = (
    os.getenv("SUPABASE_SERVICE_ROLE_KEY")
    or os.getenv("SUPABASE_SERVICE_KEY")
    or os.getenv("NEXT_PUBLIC_SUPABASE_ANON_KEY")
)

The client is created lazily on the first request that needs it, not at import time. A backend with no Supabase variables starts, answers GET /api/health/, and raises ValueError: Supabase URL and Key are required on the first route that touches the database.

That is the whole list. Older READMEs, start_local.sh and frontend/deploy.sh mention NEXT_PUBLIC_SUPABASE_URL and NEXT_PUBLIC_SUPABASE_ANON_KEY for the frontend. No file under frontend/app, components, lib or games reads them, and the @supabase/ssr and @supabase/supabase-js packages in package.json are not imported anywhere. Leave them out. Because the variable starts with NEXT_PUBLIC_, Next.js inlines its value into the client bundle when it compiles, so after changing it you restart npm run dev.

3.5Getting each key

Supabase. In the dashboard, open Project Settings, then the API keys page. Copy the project URL into SUPABASE_URL, the service_role key into SUPABASE_SERVICE_ROLE_KEY, and the anon key into NEXT_PUBLIC_SUPABASE_ANON_KEY. Newer dashboards list these JWT-style keys under a "legacy" tab beside the newer publishable and secret keys; the backend was written and tested against the anon and service_role pair. The service-role key is a root credential for your project. It goes in backend/.env and nowhere else.

OpenRouter. Create an account at openrouter.ai, add a small amount of credit, and create a key under Settings, Keys. Put it in OPENROUTER_API_KEY. The backend talks to https://openrouter.ai/api/v1 through the openai Python package, so any model id OpenRouter lists can go in OPENROUTER_MODEL. A cheap fast model is the right default; each question request is one model call of up to 25 questions (MAX_LLM_QUESTIONS in src/services/agent.py).

YouTube Data API. In Google Cloud Console, create a project, enable "YouTube Data API v3", and create an API key. Put it in YOUTUBE_API_KEY.

Serper. Sign up at serper.dev and copy the API key into SERPER_API_KEY.

Video search tries the providers in a fixed order and the first one that returns results wins: YouTube if its key is set, then Serper if its key is set, then DuckDuckGo through the ddgs package, which needs no key. Results are cached in memory for 24 hours per exam, section and topic (CACHE_TTL_SECONDS in src/services/videos.py), and only non-empty results are cached. Chapter 10 covers the ranking.

CORS. Locally you can leave ALLOWED_ORIGINS unset, because http://localhost:3000, http://localhost:3001 and the 127.0.0.1 forms of both are hard-coded in src/main.py. Set it only if you serve the frontend from another origin, such as a LAN address to test on a phone.

3.6What works with no optional keys

With only the Supabase variables set, the app is complete enough to develop almost anything:

  • Accounts, profiles, scores and stats work. They need Supabase and nothing else.
  • SAT questions still come from the real College Board question bank. ExamLearningAgent.generate_questions calls CollegeBoardSource.fetch for SAT before it considers the model, and that public API needs no key. Only the shortfall goes to _questions_from_llm, which logs "OPENROUTER_API_KEY not set" and returns nothing.
  • GRE questions come from the offline bank. When the API returns no questions, fetchAIQuestions in frontend/lib/api/questions.ts falls back to getBankQuestions from frontend/lib/questionBank.ts.
  • Games run entirely in the browser from frontend/games/ and only need questions and a place to save the score.
  • Lessons are static content in frontend/lib/lessons.ts and frontend/lib/courses.ts.
  • Lesson videos use DuckDuckGo, which rate limits after a burst of searches. An empty video list during development is usually that, not a bug.
  • Material uploads still parse PDFs and text with the rule-based parser in src/services/material_parser.py; the AI pass that finds more questions is skipped.

Without Supabase you can load the landing page and the backend health check, and nothing more. frontend/middleware.ts redirects /dashboard, /games, /learn, /materials, /mock, /profile and /stats to /login unless an auth_token cookie is present, and only the backend can issue one.

3.7Running the two servers

Backend

cd backend
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
uvicorn src.main:app --reload --port 8000

Run uvicorn from backend/, because every import is absolute from the src package (from src.api import auth). python src/main.py also works: its __main__ block puts backend/ on sys.path and starts uvicorn on 0.0.0.0:8000 with reload. backend/run.sh wraps that second form and installs the requirements if fastapi is missing. Interactive API docs are at http://localhost:8000/docs.

Frontend

cd frontend
npm install
npm run dev

The dev server listens on http://localhost:3000. Open it, sign up, and the three-step sign-up creates your profile and drops you on the dashboard.

Both at once

start_local.sh at the repository root starts both in the background, writes backend.log and frontend.log, and stops both on Ctrl+C. If backend/.env or frontend/.env.local is missing it writes a stub, so copy the .env.example files first; its stub uses underscore placeholders and omits the optional keys.

3.8Verifying the setup

curl http://localhost:8000/api/health/
# {"status":"healthy","service":"NYU Hacks Arcade API"}

curl http://localhost:8000/api/health/supabase
# {"status":"healthy","supabase":"connected","database":"accessible"}

The first route proves the process is up. The second creates the Supabase client and selects one row from game_sessions, so it proves the URL, the key and the schema in one call. It always answers 200; read the status field, and on failure the error field carries the exception text. Note the trailing slash on /api/health/: the router declares "/", so the bare path answers with a redirect.

Then do the real check: sign up in the browser, play one round of any game, and open /stats. A row in game_sessions in the Supabase table editor means the whole path works.

Two scripts in backend/ no longer work: setup.sh and start.sh import config and run main.py from the backend root, and neither file exists there any more (they moved under src/). check_server.sh still works; it checks port 8000 and a CORS preflight.

3.10Study notes

Read in this order

  1. backend/.env.example and frontend/.env.example, the short form of this chapter.
  2. backend/src/utils/database.py, for the key lookup order and the lazy client.
  3. backend/src/main.py, for .env loading, the CORS list and the router prefixes.
  4. backend/database/reset.sql, then add_materials.sql, the schema you just built.
  5. backend/src/api/health.py, the two checks you ran.
  6. frontend/lib/api/client.ts, the only place the frontend reaches the network.
  7. frontend/middleware.ts, for why signed-out pages redirect.

Check yourself

The backend starts and /api/health/ is healthy, but .env is empty. When does it fail?

On the first request that calls Database.get_client(), which raises ValueError because the client is built lazily, not at import.

You ran reset.sql on a new project. What else must you run?

add_materials.sql, because reset.sql does not create materials or custom_questions.

Why does the frontend not need any Supabase key?

It never talks to Supabase. All auth and data calls go through the FastAPI server, which holds the service-role key.

With no OPENROUTER_API_KEY, where do SAT questions come from?

The public College Board question bank, through CollegeBoardSource.fetch. Only GRE falls back to the offline bank in frontend/lib/questionBank.ts.

You changed NEXT_PUBLIC_API_URL and the browser still calls the old URL. Why?

NEXT_PUBLIC_ values are inlined when Next.js compiles. Restart the dev server (or rebuild and redeploy in production).
