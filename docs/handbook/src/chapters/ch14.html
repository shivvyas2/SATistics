Chapter fourteen

14API reference

Every HTTP route the FastAPI backend serves: twenty-four of them, counting two explicit OPTIONS handlers, across eight routers and the root. For each, the method and path, whether it needs a token, what it accepts, what it returns, how it fails, and which frontend function calls it. The last sections cover how the frontend client sends tokens and turns errors into exceptions.

The routers are mounted in backend/src/main.py with app.include_router, each under a prefix: /api/health, /api/auth, /api/games, /api/stats, /api/questions, /api/profile, /api/learn and /api/materials. The handlers are in backend/src/api/*.py. FastAPI also serves its generated documentation at /docs and the schema at /openapi.json, which are the quickest way to try a route against a local server on port 8000. The TypeScript file backend/src/api/games.ts is a leftover reference implementation and is not served.

14.1Conventions

  • Auth. "Required" means the route depends on get_current_user from api/auth.py: an Authorization: Bearer <token> header carrying the Supabase access token from login. No header gives 401 Missing authorization token; a token Supabase does not accept (forged, expired or revoked) gives 401 Invalid or expired token. AuthService.get_user verifies each token with Supabase and caches the result for up to 300 seconds (13.7).
  • Errors. Every error body is {"detail": ...}. For an HTTPException, detail is a string. For a request that fails validation, it is FastAPI's 422 list of {loc, msg, type} objects. An unhandled exception becomes 500 {"detail": "Internal server error"} from the global handler in main.py, without CORS headers.
  • Trailing slashes. Two routes are declared as "/", so their canonical paths end in a slash: /api/health/, /api/questions/. A request without the slash gets a 307 redirect. /api/profile and /api/materials are declared as "" and have no slash.
  • Naming. Request bodies for games use camelCase (gameId, correctAnswers); rows read from the database come back snake_case (game_id, correct_answer). Both styles are in use; follow the neighbouring route.

Examples use two placeholders: $API for the base URL and $TOKEN for an access token.

export API=http://localhost:8000
export TOKEN=<access token from /api/auth/login>

This is the slowest route in the API. It fetches from College Board, may search the web and calls an LLM through OpenRouter, so it can take many seconds. apiClient.getQuestions, which calls it without use_agent, is unused and would always get an empty list.

  -H "Authorization: Bearer $TOKEN"

14.9The frontend client

frontend/lib/api/client.ts exports one instance, apiClient, of the class ApiClient. Its base URL is NEXT_PUBLIC_API_URL, defaulting to http://localhost:8000; next.config.js repeats the same default. The browser calls the backend directly on that origin. frontend/vercel.json has an /api/:path* rewrite to a placeholder Railway URL, but the client never uses relative /api paths, so that rewrite does nothing.

Tokens

The client keeps auth_token, auth_refresh_token and auth_expires_at in localStorage; the constructor falls back to the auth_token cookie for the access token, and to the JWT's exp when no expiry is stored. setSession(tokens) writes them, plus the cookie with a max-age of COOKIE_MAX_AGE_SECONDS (400 days) and SameSite=Lax; the cookie only tells the middleware someone is signed in. setSession(null) clears everything. login and signup call setSession when the response has an access_token; logout calls setSession(null) in a finally, so the session is cleared even if the request fails. A storage listener keeps tabs in sync.

The private send refreshes the session first when the token expires within REFRESH_MARGIN_SECONDS (60), and once more after a 401, then retries. Concurrent callers share one refresh through refreshing, and doRefresh first reloads storage to adopt a newer session from another tab. A refused refresh (401 or 400) calls endSession: it clears the session, fires SESSION_ENDED_EVENT and, on a protected path (isProtectedPath from lib/routes.ts), goes to /login?expired=1&redirect=.... A network failure during a refresh does not sign out.

Requests and errors

The private request<T>(endpoint, options) sets Content-Type: application/json and calls send, which adds Authorization: Bearer when a token is held and fetches with mode: 'cors' and credentials: 'include'. On a non-2xx response it parses the body (falling back to {detail: statusText}) and throws new Error(error.detail || 'HTTP error! status: N'). On success it returns parsed JSON when the content type is JSON, else {}. Every failure is logged with console.error('API request failed:', ...) and rethrown.

Three consequences follow. The status code is lost: callers see only a message, so a 401 and a 500 look alike once send has tried a refresh. A 422 has a list in detail, and request uses detail only when it is a string, so a validation error reaches the page as "HTTP error! status: 422" without saying which field failed. And a CORS-less 500 surfaces as a TypeError from fetch, not as the server's message.

uploadMaterial is the one method that bypasses request: it builds a FormData and calls send without a Content-Type so the browser sets the multipart boundary, and throws body.detail the same way. getUserStats and getRecentSessions catch everything and return null and []. getQuestions and getTopics have no callers.

14.10Adding a route

  1. Put the handler in the router file for its area under backend/src/api/, or a new file registered in main.py with a prefix and tag.
  2. Depend on get_current_user and get_db; filter every query by current_user["id"].
  3. Define request and response models in backend/src/models/schemas.py with real constraints, and set response_model.
  4. Raise HTTPException with a sentence a user can read; do not put str(e) in it.
  5. Add a typed method to ApiClient and call it from the page, not fetch.
  6. Add the route to this chapter.

14.11Study notes

Read in this order

  1. backend/src/main.py, the prefixes, CORS and the exception handler.
  2. backend/src/api/auth.py, for get_current_user, which most routes depend on.
  3. backend/src/models/schemas.py, every request and response shape in one place.
  4. backend/src/api/profile.py and stats.py, the simplest authenticated routes.
  5. backend/src/api/questions.py, the optional-auth route and the agent call.
  6. backend/src/api/materials.py, multipart input and ownership checks.
  7. frontend/lib/api/client.ts, the other end of every row in this chapter.

Check yourself

A game calls GET /api/questions/?limit=10 and gets {"questions": [], "total": 0}. Why?

use_agent defaults to false, and without it the route builds no questions. Send use_agent=true, as getAIQuestions does.

The profile page shows the error "HTTP error! status: 422". Why is there no better message?

Validation errors put a list in detail, and request only passes detail on when it is a string. The list, with the failing field, is in the response body in the browser's network panel.

Which material route reports success even when the id does not belong to the caller?

DELETE /api/materials/questions/{id}. It deletes nothing (the user filter matches no row) but always returns {success: true}.

Why does uploadMaterial not use request()?

request() forces Content-Type: application/json. A multipart body needs the browser to set the content type with its boundary.

Which fields of GameAnalytics does the server ignore?

The inner gameId, accuracy, each topic's accuracy, and everything in streakInfo except maxStreak.
