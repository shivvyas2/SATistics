Appendix A

AGlossary and reading order

The words the code and the product use, defined the way the code uses them and pointed at the file where each one lives, followed by four routes through the repository: one for frontend work, one for games, one for the backend, and one for questions and AI.

The glossary has three parts: the exam vocabulary the product is built on, the project's own terms, and the infrastructure terms that show up in the code. Paths are relative to the repository root. Where a term means something narrower here than it does in general, the definition says so.

A.1Exams and study

TermMeaning hereWhere
SATThe digital SAT. Exam id sat. Sections are Math (quant, 95 seconds per question) and Reading & Writing (verbal, 71 seconds). Four answer choices. Target scores 400 to 1600.EXAMS in frontend/lib/exam.ts and backend/src/services/question_sources.py; Profile in schemas.py
GREExam id gre. Sections are Quantitative (quant, 105 seconds) and Verbal (verbal, 90 seconds). Five answer choices in the backend's settings. Target scores 260 to 340.Same files
ExamWhich test a user studies for: sat or gre. Stored on the profile, on each material, and in the browser's exam_prefs.ExamId in lib/exam.ts
SectionThe half of an exam a question belongs to. Always one of two ids: quant or verbal, whatever the exam calls them on screen.SectionId in lib/exam.ts
Quant, verbalThe two section ids. quant is SAT Math or GRE Quantitative; verbal is SAT Reading & Writing or GRE Verbal.lib/exam.ts; materials.section check constraint
Exam prefsThe exam, section and question count (6, 10 or 20) a player picked. Kept in localStorage as exam_prefs.getExamPrefs, setExamPrefs, QUESTION_COUNTS
CourseOne exam section presented as a course: a title, a summary and its topics. There are four: SAT Math, SAT Reading & Writing, GRE Quant, GRE Verbal.COURSES in frontend/lib/courses.ts
TopicA content area inside a course, matching the official content domains (for SAT Math: Algebra, Advanced Math, Problem-Solving and Data Analysis, Geometry and Trigonometry). Every question carries one, and stats are kept per topic.Course.topics; question_attempts.topic
DomainThe College Board's name for what the app calls a topic. The code comment calls topics "official content domains".lib/courses.ts
SkillA finer label under a topic on official questions, such as Words in Context or Boundaries. Used for quick-pace filtering and for hints.Question.skill; QUICK_SKILLS in question_sources.py; lib/hints.ts
Difficultyeasy, medium or hard. The agent recommends one from the user's accuracy (under 50% easy, over 75% hard).DIFFICULTIES; analyze_performance in agent.py
Pace: quick, deepWhat kind of question a game needs. quick games want short questions answerable in seconds; deep games take passages and multi-step problems. Squid Game is the only deep game.Pace, gamePace, DEEP_GAMES in lib/exam.ts; is_quick_question
Weak topic, strong topicA topic answered under 50% correct in a session is weak; 80% or more is strong. The lists in user_stats are merged session by session, and a topic moves between them. The agent asks for more questions in weak topics._update_user_stats in game_service.py; CollegeBoardSource._pick_candidates
Mock examA timed, game-free test at the real exam's pace, in three lengths: quick (10 questions), module (22 or 27 SAT, 12 GRE) and section (two modules). It ends with a rough scaled-score estimate and is saved as a session with game id mock-exam.frontend/app/mock/page.tsx
Target score, test date, daily minutesThe goal fields on a profile. Daily minutes is 5 to 240 on the server; the form offers 10, 20, 30 or 45.Profile in schemas.py; DAILY_MINUTES in lib/profile.ts

A.3Infrastructure terms

TermMeaning hereWhere
SupabaseHosted Postgres plus Auth. The backend uses both through one Python client; the frontend does not use it at all.backend/src/utils/database.py
Service-role keyThe Supabase key that bypasses Row Level Security. The backend reads it from SUPABASE_SERVICE_ROLE_KEY (or SUPABASE_SERVICE_KEY) and uses it for every query.Database.get_client
Anon keyNEXT_PUBLIC_SUPABASE_ANON_KEY. Subject to RLS. Only a fallback in the backend.database.py, config.py
RLSRow Level Security: Postgres policies that limit rows to auth.uid() = user_id. Enabled on all six tables, bypassed by the service role, so the backend's own filters are the real access control.backend/database/*.sql; 13.5
Access token, auth_tokenThe Supabase JWT returned by login and sent as a bearer header. The browser keeps it in localStorage and in a cookie both named auth_token.frontend/lib/api/client.ts; frontend/middleware.ts
get_current_userThe FastAPI dependency that turns a bearer token into {id, email} or a 401.backend/src/api/auth.py
Guest user idThe all-zero UUID the question route passes to the agent when no one is signed in.backend/src/api/questions.py
Sanitized HTMLOfficial question HTML and MathML re-rendered from an allowlist of tags and attributes, in the *Html fields.backend/src/utils/html_utils.py; components/QuestionContent.tsx
OpenRouterThe LLM gateway the agent and the material parser call, through the OpenAI SDK, with OPENROUTER_API_KEY and model OPENROUTER_MODEL (default anthropic/claude-haiku-4.5).backend/src/services/agent.py; backend/src/config.py
CUSTOM_ID_OFFSET1,500,000,000, added to a custom question's database id so it does not clash with ids from other sources.services/custom_questions.py

Check yourself

What is the difference between a session and a login?

A session is one finished game or mock exam, a row in game_sessions. A login produces an access token; the code never calls that a session.

Which question sources can produce sanitized HTML?

Only official. Web, AI, custom and practice questions are plain text.

Which game is deep pace, and what does that change?

Squid Game. It is sent pace=deep, so the sources may return passages and multi-step problems; quick games get only short questions.
