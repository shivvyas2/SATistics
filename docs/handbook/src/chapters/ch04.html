Chapter four

4The design system

SATistics looks like a filled-in answer sheet that learned to play games: thick ink outlines, hard offset shadows, flat blocks of cobalt and lime, and the occasional frosted glass panel floating over soft paper. The whole system is small. It is seven color tokens and four shadows in the Tailwind config, a dozen component classes in one stylesheet, two fonts, a handful of SVG brand pieces and one app shell. This chapter walks through each of them and ends with the rules for building a screen that fits.

There is no component library and no design token package. Pages are client components that compose Tailwind utilities with the classes in frontend/app/globals.css. That keeps the system easy to read and easy to break, so most of this chapter is about the conventions the existing screens follow rather than about APIs.

4.1Two ideas: brutal and glass

The comment above the component layer in globals.css names the identity in one line: "brutalist outlines with frosted glass panels". The two halves do different jobs.

Neo-brutalism carries anything you can press or anything that holds content. It is a 2 px ink border, a solid offset shadow with no blur, generous radii (16 to 32 px), and flat fills from the palette. Buttons move toward their shadow when hovered and sink into it when pressed, which makes the shadow read as physical depth. Cards, form fields, chips, the shell's outer frame and the game covers all use the same outline.

Glass is for decoration and for secondary panels that sit over something busy: the landing page's section nav, the "how it works" steps, the key idea cards on a lesson, the caption on the developer page and the "Today's focus" card on the auth screens. It is a translucent white fill, a thin white border, a soft blurred shadow and backdrop-blur-xl. Glass only works over something with texture, which is why the app's background is the .paper-blobs gradient rather than a flat color.

The brand motif is the exam answer sheet. The logo mark is four answer bubbles laid out like a gamepad's face buttons, a decorative BubbleRow shows A to D with one bubble filled, and a Pencil draws a No. 2 test pencil in coral, paper and lime.

4.3Tokens

All tokens live under theme.extend in frontend/tailwind.config.js, so the default Tailwind palette is still available. The house rule is to use the tokens and nothing else for color; the only other hues in the codebase are the pink #F45D9C that appears as an avatar swatch and in cover art, and the neon colors inside the arcade games.

TokenValueSoft variantUsed for
paper#ECEAE4nonePage background, the html element, .theme-paper
ink#17171CnoneText, every outline, every hard shadow, the active nav item
cobalt#3A33E8#DCDBFBPrimary accent, links, focus ring, hero cards, filled bubbles
lime#D4F34A#F1FBC9Call to action, success, "learned", strong topics
coral#FF6B4A#FFE1D9Errors, wrong answers, weak topics, traps
mist#F7F6F2noneThe shell's inner surface, .btn-paper, light HUD chips

cobalt, lime and coral are objects with a DEFAULT and a soft key, so both bg-lime and bg-lime-soft exist. The soft variants are tints for large areas (a lesson's traps section is bg-coral-soft, a quick check is bg-cobalt-soft); the full colors are for small, loud things.

Four shadows are defined. shadow-brutal is 4px 4px 0 0 in ink, shadow-brutal-sm is 2 px and shadow-brutal-lg is 8 px (used once, on the shell's outer frame). shadow-glass is a large soft drop shadow plus a one-pixel white inset highlight. Hover states that need a 5 px or a cobalt shadow write an arbitrary value instead, for example shadow-[3px_3px_0_0_#3A33E8] on the active nav link and on a focused field. The config also adds rounded-4xl (2 rem), though most screens write radii such as rounded-[24px] directly.

Two font families are declared: font-display reads the CSS variable --font-display and font-serif reads --font-serif, each with a system fallback. Section 4.5 covers where those variables come from.

4.4Component classes

globals.css defines its reusable pieces inside @layer components with @apply, so they sort before utilities and any utility on the same element wins. That is deliberate: className="btn btn-ink w-full py-3.5" overrides the button's padding without a specificity fight.

ClassWhat it applies
.theme-papermin-h-screen bg-paper text-ink. Put it on the root of every non-game screen.
.brutal2 px ink border and shadow-brutal. The outline on its own.
.glassborder-white/70 bg-white/55 shadow-glass backdrop-blur-xl.
.btnInline flex, rounded-2xl, ink border, bold 15 px text, shadow-brutal. Hover lifts by one pixel and grows the shadow to 5 px; active shifts 3 px and drops the shadow; disabled is half opacity with no pointer events.

.chipSmall pill with an ink border and semibold text, for tags, toggles and topic lists.
.paper-blobsThree radial gradients (two white, one cobalt-soft) over paper. Outside the layer, plain CSS.

Below the component layer the file sets a global :focus-visible ring (3 px solid cobalt, 3 px offset) and a prefers-reduced-motion rule that cuts every animation and transition to 0.01 ms. It also holds styles that belong to other features: .question-content for exam questions rendered from HTML and MathML, .dark-scroll, .game-hud and .game-reading for text over game scenes, the .arcade-* classes and the .hud-panel skins described in section 4.8.

Two leftovers. The body rule sets background: #0a0a0a and color: #fff, from when every screen was dark. The html element is paper, and every current screen paints its own background, so you only see it if a page forgets .theme-paper. About 400 lines of .retro-* Game Boy classes are still in the file; their only user is frontend/components/GameCard.tsx, which nothing imports.

4.5Type

frontend/app/layout.tsx loads two Google fonts with next/font/google, which self-hosts them at build time. Bricolage_Grotesque becomes the CSS variable --font-display; Instrument_Serif, at weight 400 in normal and italic, becomes --font-serif. Both use display: 'swap'. The root <html> carries both variable classes and <body> carries font-display, so the grotesque is the default everywhere.

Headings are heavy and tight: font-extrabold tracking-tight at text-4xl or text-5xl for a page title, text-2xl or text-xl for a section. The serif is an accent and only ever appears in italic, as the second line of a big headline: "Your score, leveled up." on signup, "Back for another round?" on login, "one game at a time." on the landing page. The pattern in JSX is a <span className="block font-serif font-normal italic"> inside the <h1>. Do not set body copy in the serif.

A third font, Press_Start_2P, is loaded in frontend/lib/arcade.ts as --font-arcade. It is exported as arcadeFontVariable and only applied inside ArcadeFrame, so the pixel font is downloaded only on pages that use it.

4.6Brand components

frontend/components/brand/Logo.tsx exports four pieces. Logo is the wordmark: the text "SATistics" in 22 px extrabold inside a Link, with an inverted prop for white on cobalt and an href that defaults to / (the shell passes /dashboard). LogoMark is the square icon: an ink tile with rounded corners, a lime bubble on top and three outlined bubbles, inverted to a white tile with cobalt rings when asked. BubbleRow draws four lettered bubbles and fills the one at index filled (default 2, so C) in cobalt. Pencil draws the pencil. All three SVGs are aria-hidden; they are decoration.

Icons.tsx holds 17 stroke icons on a 24 by 24 grid: ArrowUpRight, ArrowLeft, HomeIcon, GamepadIcon, ChartIcon, UserIcon, SearchIcon, LogoutIcon, CheckIcon, PlayIcon, MenuIcon, CloseIcon, BookIcon, UploadIcon, ExpandIcon, ShrinkIcon and ClockIcon. A shared base() helper gives each one stroke="currentColor", a 2.2 stroke width, round caps and joins, aria-hidden, and a default size of h-5 w-5. Color an icon by setting the text color of its parent; size it with a className. Add new icons here in the same shape rather than pulling in an icon package.

GameCover.tsx draws a cover for each game as SVG on a 300 by 400 view box, using constants that mirror the tokens (INK, PAPER, LIME, COBALT, CORAL, plus PINK). The COVERS record has an entry, a background color and an art fragment, for zombie, whackamole, carnival, subway-surfers, squid-game and pac-man. The zombie cover is a lime crosshair over a zombie hand in front of two answer tombstones; Whack-A-Mole is a cobalt mole holding a "B" card under a coral mallet. A small letter() helper places an answer letter in the display font. Unknown ids get FALLBACK, a lime circle on ink.

The SVG uses preserveAspectRatio="xMidYMid slice" and fills its parent absolutely, so the parent decides the shape: aspect-[3/4] on the auth screens, a square w-16 thumbnail in session lists, a circle on the dashboard. With showTitle on (the default) the game's title from GAME_META sits in a white outlined label at the bottom left. A new game needs an entry in COVERS or it will show the fallback everywhere.

4.7The app shell

Every signed-in page renders inside DashboardLayout from frontend/components/DashboardLayout.tsx. It takes children, an optional aside and an asideWide flag. The outer div is theme-paper paper-blobs; inside it a bg-mist/80 panel becomes, from lg up, a rounded 32 px frame with an ink border and shadow-brutal-lg that fills the viewport, with its own scrolling main column.

The sidebar shows the Logo, then the signed-in person's Avatar (76 px, from components/profile/ProfileFields.tsx), name and @username, read through useAccount. While the account loads, a pulsing outlined circle stands in. The NAV array lists seven links: Home, Learn, Games, Mock exam, My material, Statistics and Profile. A link is active when the path matches exactly, except Games and Learn, which match by prefix so a lesson or a game's select page keeps its tab lit. The active link is an ink pill with white text and a cobalt offset shadow, and carries aria-current="page".

At the bottom, a dashed goal card shows the exam's target score and either a test-day countdown (from daysUntil) or the daily minutes. If the account has no profile, a lime "Set up your profile" link takes its place. "Log out" calls apiClient.logout(), clears the account cache and pushes to /login whether or not the request succeeded.

Below lg a top bar holds the logo and an .arrow-btn menu toggle with aria-expanded and a label that flips between "Open menu" and "Close menu". The menu renders the same sidebar markup inline. The aside column is hidden xl:block, so anything a page puts there is invisible below 1280 px unless the page repeats it in the main column. The lesson page does this (its video panel has an xl:hidden copy); the dashboard does not, so its courses, focus topics and "Haven't tried yet" covers do not appear on tablets or phones.

Signed-out screens use AuthShell instead: a cobalt showcase panel on the left from lg up (logo, a headline, a caption, three tilted GameCovers behind a glass card) and the form column on the right, capped at 440 px. It also exports Field, which pairs a bold label with an optional hint, and FormError, a coral-soft box with role="alert".

4.8Inside the games

Games run full screen over 3D or canvas scenes, so they do not use the shell. There are three looks, chosen per game.

Site-styled HUD. frontend/components/arcade/GameHud.tsx brings the brutal outline into the game. HUD_PANEL is a class string for an ink card with a lime offset shadow, used for question panels; question cards are styled for a dark background, so the panel stays ink even on a light scene. GameTopBar puts a round pause button on the left and a row of stat chips in the middle, each chip toned paper, lime, cobalt (soft) or coral (soft) through a TONES map. An empty 44 px span on the right balances the pause button so the chips stay centered. Pips draws filled and empty dots for lives or shots and labels itself "3 of 5" for screen readers. Whack-A-Mole, Balloon Pop and Pac-Man use this set.

Arcade cabinet. ArcadeFrame.tsx wraps a game in a fixed black screen that sets --arcade-color from its color prop, applies the pixel font variable and lays the .arcade-crt scanline and vignette overlay on top. ArcadeTopBar is a marquee of red labels over glowing values, with pause and mute buttons; ArcadeStartScreen is the attract screen with a zero-padded "HI-SCORE", a START button, a blinking "INSERT COIN" and a plain "Back to games" link. High scores come from getHighScore and recordHighScore in lib/arcade.ts, stored in localStorage under arcade_hi_<gameId>. Only the zombie game uses this frame today.

Themed skins. Subway Surfers and Squid Game use .hud-panel, whose background, accent, radius and shadow come from CSS variables. .skin-subway sets yellow on deep navy with squared corners, like station signage; .skin-squid sets tracksuit green with a guard-pink offset shadow. .hud-banner paints a strip in the accent color across the top of a panel. A new skin is four variables in a new .skin-* class.

4.9Words

The copy is part of the system and follows a few rules you can check by reading any screen.

  • Sentence case everywhere. "Mark as learned", "Set up your profile", "Recent sessions", "Haven't tried yet". Never Title Case on buttons or headings. The arcade attract screen is the one place that shouts in capitals, on purpose.
  • No emoji in the interface. Icons come from Icons.tsx. The arcade top bar's menu and music glyphs are text symbols inside labelled buttons. The name fields in frontend/lib/games.ts still carry older titles with emoji; show titles through gameTitle from frontend/lib/gameMeta.ts instead.
  • Plain verbs on buttons. "Log in", "Continue", "Create profile", "Open lesson", "Practice in a game", "Play Whack-A-Mole". Say what will happen.
  • Talk to one person, briefly. "Your account is ready. Finish your profile to start." Empty states say what will fill them: "Finish a game and your score, accuracy and streak show up here."
  • Errors say what to do. "Usernames are 3 to 24 lowercase letters, numbers or underscores." "The username @maya is taken. Try another one." End sentences with a period.
  • Loading text ends in an ellipsis character: "Logging in…", "Finding a video lesson…".

4.10Building a new screen

A new signed-in page is a client component in frontend/app/<name>/page.tsx. Follow the shape of frontend/app/stats/page.tsx, which is the simplest complete example.

  1. Wrap the page in <DashboardLayout>. Add the route to the NAV array if it deserves a tab, and to protectedPrefixes in frontend/middleware.ts if it needs a login.
  2. Inside, use <div className="mx-auto max-w-4xl p-5 sm:p-8"> (or max-w-3xl for reading, max-w-5xl for grids).
  3. Open with an h1 in text-5xl font-extrabold tracking-tight and a one-sentence text-ink/65 description under it.
  4. Group content in cards: rounded-[24px] border-2 border-ink bg-white p-5. Promote the one most important card with a fill (bg-cobalt text-white or bg-lime) and shadow-brutal. Use soft tints for status, never for decoration.
  5. Use .btn with one variant for actions. One btn-ink or btn-lime per view is the primary action; others are btn-paper.
  6. Show skeletons while loading (animate-pulse rounded-[22px] bg-white at the size of what is coming), and a dashed outlined box with a next step when empty.
  7. If you use aside, decide what small screens see instead.

A minimal page looks like this: 

'use client'
import { DashboardLayout } from '@/components/DashboardLayout'

export default function ExamplePage() {
  return (
    <DashboardLayout>
      <div className="mx-auto max-w-4xl p-5 sm:p-8">
        <h1 className="text-5xl font-extrabold tracking-tight">Example</h1>
        <p className="mt-2 max-w-xl text-ink/65">One sentence on what this page is for.</p>
        <section className="mt-8 rounded-[24px] border-2 border-ink bg-white p-5">
          <h2 className="text-xl font-extrabold">A section</h2>
          <button className="btn btn-ink mt-4">Do the thing</button>
        </section>
      </div>
    </DashboardLayout>
  )
}

4.11Accessibility rules

The codebase already follows these; keep doing so.

  • Never remove the focus ring. :focus-visible draws a cobalt outline on everything. .field sets outline-none but replaces it with a cobalt shadow; if you suppress an outline, replace it.
  • Respect reduced motion. The global rule already zeroes transitions and animations. Do not drive essential state changes with animation alone, and add a prefers-reduced-motion override for any keyframe animation you add, as .arcade-blink does.
  • Label icon-only buttons. The menu toggle, the pause button, the back arrow on signup, the play overlay on a video thumbnail and each avatar swatch all carry an aria-label.
  • Expose state. Toggles use aria-pressed (exam choice, daily minutes, avatar color, "Mark as learned"), nav uses aria-current="page", the signup steps use aria-current="step".
  • Announce results. Errors render in FormError with role="alert"; quick check feedback and "Profile saved" sit in aria-live="polite" regions.
  • Decorative SVG is hidden. Logo marks, bubbles, the pencil, covers and icons are all aria-hidden. Do not put meaning only in a cover; put the game's title in text beside it.
  • Keep contrast. Ink on paper, mist, white, lime and every soft tint is high contrast. White text goes on ink, cobalt and coral only. Muted text uses text-ink/55 to text-ink/70; do not go lighter for anything a person needs to read. avatarTextColor switches to ink on the lime swatch for the same reason.
  • Label every field. Use Field with a matching htmlFor and id, and group choice buttons in a fieldset with a legend.

4.12Study notes

Read in this order

  1. frontend/tailwind.config.js, the whole token set in 40 lines.
  2. frontend/app/globals.css, the first 90 lines, then the game sections from .game-hud down.
  3. frontend/app/layout.tsx, how the fonts become CSS variables.
  4. frontend/components/DashboardLayout.tsx, the shell and its breakpoints.
  5. frontend/components/auth/AuthShell.tsx, glass over cobalt, and Field.
  6. frontend/components/brand/Logo.tsx and GameCover.tsx.
  7. frontend/components/arcade/GameHud.tsx, then ArcadeFrame.tsx.
  8. frontend/app/stats/page.tsx, a whole screen built from these parts.

Check yourself

Why can a page write btn btn-ink py-3.5 and get the larger padding?

Because .btn is declared in @layer components, which Tailwind emits before the utilities layer. The py-3.5 utility comes later in the cascade with the same specificity, so it wins.

Where does font-serif get its typeface, and what happens if the font fails to load?

layout.tsx loads Instrument Serif through next/font/google as the variable --font-serif on <html>; Tailwind's font-serif reads that variable and falls back to Georgia, then the generic serif.

You add a seventh game and its card shows a lime circle on black. Why?

GameCover found no entry for the new id in COVERS and used FALLBACK. Add cover art keyed by the game's id.

A page passes a helpful panel as aside. A tester on an iPad says it is missing. What is going on?

The aside column is hidden xl:block, so it only renders at 1280 px and wider. Render the same content in the main column with xl:hidden, as the lesson page does with its videos.

Why is the app's background a gradient rather than flat paper?

Glass panels blur what is behind them. Over a flat color the blur has nothing to work on and the panel looks like a grey box; the .paper-blobs gradients give it soft texture to frost.
